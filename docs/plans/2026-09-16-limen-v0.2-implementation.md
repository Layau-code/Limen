# Limen v0.2 用量与成本结算实施计划

> **For agentic workers:** 按任务顺序执行，每个任务先写失败测试，再写最小实现。保持生产方法有简体中文用途注释；不要引入 Web 框架、数据库或额外 Provider。

**目标：** 在不破坏现有 OpenAI 兼容接口、Fallback、SSE 实时转发和取消传播的前提下，采集 Provider 报告的 Token，按目标价格计算成本，并在响应结束后通过安全日志和 HTTP Trailer 暴露结算结果。

**架构：** 配置层把每个目标的十进制定价解析为定点整数；Provider 只负责协议级 Usage 采集；Gateway 汇总一次请求的所有 attempt；HTTP 层只负责实时转发、发布 Trailer 和日志字段。Usage 采集通过有界响应观察器完成，结算失败不能改变已确定的响应。

**技术栈：** Go 1.24 标准库、`encoding/json`、`math/big` 或定点整数校验、`httptest.Server`、`slog`、现有 Router/Provider/HTTP API。

- [ ] **Step 2: 运行测试确认失败**

运行：`go test ./internal/provider -run 'Test(Usage|Observed)' -count=1`。

预期：因 `Usage`、观察器和 `Response.Usage` 尚不存在而失败。

- [ ] **Step 3: 实现小型 Usage API**

定义：

```go
type Usage struct {
    InputTokens  int64
    OutputTokens int64
    Complete     bool
}

type UsageRecorder interface {
    Snapshot() Usage
}

type Response struct {
    StatusCode  int
    ContentType string
    Body        io.ReadCloser
    Usage       UsageRecorder
}
```

普通响应观察器在每次 `Read` 时最多保留固定字节数；EOF 后解析 OpenAI `usage`。SSE 观察器按空行切分事件，限制单事件大小，只解析 usage 字段，原始字节照常返回。

- [ ] **Step 4: 运行观察器测试确认通过**

运行：`go test ./internal/provider -run 'Test(Usage|Observed)' -count=1`。

- [ ] **Step 5: 检查取消与关闭**

确保观察器的 `Close` 只关闭底层 Body 一次，不创建无法退出的后台 goroutine；运行 `go test ./internal/provider -race`。
