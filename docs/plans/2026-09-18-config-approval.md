# Limen 配置发布审批实施计划

## 目标

在不改变默认单人开发流程的前提下，为配置发布增加可选的双人审批控制面。审批只约束 `config.publish`，不扩展 Provider、Run 或凭据范围；开启后必须同时满足审批绑定、幂等键、租户和执行者分离等不变量。

## 实施顺序

1. **审批领域模型与配置开关**
   - 新增 `internal/approval`，定义 `pending`、`approved`、`consumed`、`rejected`、`expired` 状态和稳定错误。
   - 配置增加 `LIMEN_CONFIG_APPROVAL_REQUIRED`，只接受明确布尔值，默认关闭。
   - 所有领域方法接收 `tenant_id`，审批记录不保存正文或密钥。

2. **内存状态机与失败测试**
   - 先覆盖创建、重复幂等、审批者不能等于申请者、拒绝、过期和状态冲突。
   - 审批必须绑定配置版本、发布幂等键和请求哈希；不同绑定不得复用。
   - 使用可替换时钟测试过期，不依赖真实等待。

3. **持久化与原子发布**
   - 增加 PostgreSQL 审批表、操作幂等表、组合主键、RLS 和 `FORCE ROW LEVEL SECURITY`。
   - PostgreSQL 配置发布在同一事务中验证并消费审批，再写发布幂等记录和切换配置版本。
   - 内存实现保持相同可观察语义，供单元测试和单机开发使用。

4. **HTTP 控制面接入**
   - 增加创建、查询、批准和拒绝接口，全部使用 Bearer 鉴权、`configs:write`/`configs:read` 和 `Idempotency-Key`。
   - 开启审批后，发布必须携带 `X-Limen-Approval-ID`；同一发布键重试只能重放同一结果。
   - 将领域错误映射为稳定的 `approval_*` 错误码，并为每个状态变更追加安全审计事件。

5. **验证与文档**
   - 增加并发幂等、跨租户隔离、过期、重试和 Router 激活失败后的恢复测试。
   - 运行 `make check`、PostgreSQL 集成测试、构建和 `git diff --check`。
   - 同步 `README.md`、`AGENTS.md`、`docs/design.md` 和 `CHANGELOG.md`，明确默认关闭和生产要求。

## 验收不变量

- 同一租户、配置版本和发布幂等键最多对应一条有效审批。
- 申请者不能批准或拒绝自己的审批；静态开发身份不能满足双人审批。
- 审批只对绑定的版本、发布键和请求哈希有效，不能跨发布复用。
- 审批过期或状态冲突时不切换配置；重复请求不会重复切换或重复消费。
- 所有查询、状态变更和审计事件都按 `tenant_id` 隔离，响应不包含配置正文、Provider 密钥或 Prompt。
- 默认关闭时现有发布 API 行为和兼容测试保持不变。
