# Limen 配置版本熔断器生命周期计划

## 背景

配置发布会替换 Router 的模型目录，但已经创建的 Run 仍可能引用旧版本。旧 Run 执行期间必须继续使用对应目标的熔断器；如果永久保留所有历史目标，频繁发布配置会造成进程内存无界增长。

## 目标

- 当前目录中的目标始终拥有可复用的熔断器状态。
- 仍在执行的旧 Run 目标在执行结束前不能被回收。
- 没有执行引用的历史目标在下一次配置切换时回收。
- 不改变 DecisionInput、ExecutionPlan 或 Provider 协议。

## 实现

1. Router 为每个熔断器维护执行引用计数。
2. Executor 消费计划前一次性获取计划目标的熔断器引用，返回时幂等释放。
3. 配置切换只复制当前目录目标和引用计数大于零的历史目标。
4. 释放最后一个历史引用后不立即修改当前目录，避免与配置切换竞争；下一次切换统一清理。
5. 测试覆盖多版本发布不增长、活跃旧执行保留和执行结束后回收。

## 验收

```bash
go test ./internal/gateway -race -count=1
make check
go build -o /tmp/limen-breaker-lifecycle ./cmd/limen
```
