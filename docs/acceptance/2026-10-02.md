# Limen 3.0 路由与观测控制台验收

日期：2026-10-02

范围：Jev 辅助语义路由、决策快照与 Replay、影子评估持久化、权限和配置发布边界、观测控制台。

## 结论

本次代码验收通过，可以推送代码。功能默认关闭；启用语义路由仍要求配置允许公开数据出站、请求声明 `public`、凭据拥有 `semantic:external` Scope，并使用 `model=auto`。确定性决策引擎仍执行全部硬过滤。

这不是 Jev 线上效果验收。没有调用 TypeSafe 生产服务，也没有使用独立的真实任务留出集，因此目前不能据此启用生产 `active` 灰度，或声称路由质量、总成本已改善。

## 验收证据

| 范围 | 结果 | 验证 |
| --- | --- | --- |
| 构建与静态检查 | 通过 | `make check`、`make build`、`make validate` |
| 兼容与可靠性 | 通过 | `make compatibility`、`make reliability` |
| PostgreSQL | 通过 | `make integration`；包含 V3 决策回放、影子结果幂等写入及租户隔离 |
| 离线发布门禁 | 通过 | `make release-check`，包括 smoke、benchmark、demo 和 `git diff --check` |
| Jev 协议与降级 | 通过 | httptest 覆盖响应校验、错误/超时、请求并发、熔断和有界影子队列 |
| 路由安全边界 | 通过 | 验证显式模型、兼容模式、授权不足、非公开数据、关闭开关及硬过滤不会触发或绕过规则 |
| 决策一致性 | 通过 | 配置发布竞态使用同一请求快照；Replay 不联网；无候选结果能正确回放为拒绝计划 |
| 观测控制台 | 通过 | `node --test internal/web/acceptance.test.cjs`；浏览器实测连接/断开、dry-run 决策和 Replay |
| 工作区差异 | 通过 | `git diff --check` |

浏览器实测确认，live 决策不会把演示数据伪装成 Provider 调用次数或费用；缺失执行证据明确显示为未知，Jev 成本单独呈现。Replay 显示同一计划，且注明不会调用 Provider。

## 上线前仍需完成

1. 用固定版本的 Jev 生产凭据执行受控连通性与延迟检查，并确认凭据轮换和告警流程。
2. 建立经标注的中英文留出集，评估分类质量、升级率、超时/缺样比例和 Jev 成本。
3. 先运行 shadow，审阅反事实结果和总成本，再由业务负责人决定是否按租户、任务类型分阶段开启 active。

在完成这些线上证据前，建议保持 `mode=off`；需要验证数据路径时只在已授权的测试租户运行 shadow。
